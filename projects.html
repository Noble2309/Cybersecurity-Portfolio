Security workflow design · 2026

Remediation Enablement Framework

A framework and static reference prototype designed to improve two parts of the post-assessment lifecycle: structured risk acceptance and retest readiness.

Problem

Risk acceptance can be mistaken for technical closure, while retest requests often arrive without enough implementation context.

Approach

Separate business risk ownership from technical validation, retain the original finding as the authoritative record and capture structured remediation context.

Outcome

A documented framework, fictional assessment workflow and live static prototype that demonstrates the lifecycle end to end.

My contribution

Defined the framework concept, workflow boundaries, lifecycle states, fictional finding content and security requirements, then reviewed and tested the AI-assisted static reference implementation against those requirements.

02

AI governance & research · 2025 / public edition 2026

AI Accountability for SOCs

A public portfolio reconstruction of an academic research project exploring accountability, governance and bias testing for AI-enabled security operations.

Problem

AI-assisted defensive decisions can blur responsibility when models miss alerts, generate false positives or influence automated security actions.

Approach

Combine technical safeguards, regulatory alignment and ethical oversight with explicit responsibility assignment and repeatable bias testing.

Outcome

A sanitised framework package containing public templates, responsibility mappings and a synthetic worked bias-testing example.

My contribution

Developed the research question, framework design, responsibility mappings, templates, reviewer study and analysis, then produced a sanitised public portfolio edition that removes university administration and participant material.

03

LLM security methodology · 2026

LLM Prompt Injection Testing Methodology

An independent public reconstruction of prompt-injection testing work originally contributed to a broader LLM penetration-testing methodology.

Problem

Prompt injection is often demonstrated at the model level without proving a meaningful application-security boundary or impact.

Approach

Use a repeatable consultant workflow covering direct, indirect, RAG, tool, multimodal, jailbreak, obfuscated and agent-context attack paths.

Outcome

A public PI-01 to PI-10 methodology with an impact-led finding threshold, consultant checklist and current framework mapping.

My contribution

Originally contributed prompt-injection testing content to a broader private methodology, then independently rewrote and expanded the public edition with an impact-led finding threshold, agentic coverage, consultant checklist and updated framework mapping.
